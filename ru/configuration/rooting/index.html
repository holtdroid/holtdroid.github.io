Rooting a phone

How one test phone was bootloader-unlocked and rooted with Magisk, for the record, with the sites and repositories that were used.

Это содержимое пока не доступно на вашем языке.

Read before you tick anything

Holtdroid does not need root, and the phone provider does not use it yet. This page exists because one test phone was rooted to prepare for Frida and DevTools on release builds, and the process was full of traps worth writing down. It is a record of what was done to one device, not a recommendation to do it to yours. Everything here can destroy a phone.

This page is blurred on purpose. It describes how a test phone was unlocked and rooted, step by step, with the sites and repositories that were used. Before it unblurs, tick every statement below. All of them, honestly.

What this is

Section titled “What this is”

A walkthrough of unlocking the bootloader and installing Magisk on a Samsung Galaxy A05 (SM-A055M, region GTO, firmware A055MUBU5CXH1, Android 14, MediaTek MT6769), done from the Linux host that runs the phone provider, with the phone’s USB on that host. Other models differ in details (partition names, how the bootloader is unlocked, which tool can flash it); the shape of the work is the same.

What root gives Holtdroid later: Frida for DevTools on release builds, reading app data, changing the system language. What it costs on a Samsung: the Knox fuse blows the moment the bootloader is unlocked and never un-blows — Samsung Pay, Secure Folder, Samsung Health’s secure parts and the warranty are gone for good, OTA updates stop, and the boot screen warns about an unofficial OS from then on.

Tools and sources used

Section titled “Tools and sources used”
What Where Used for
platform-tools (adb) developer.android.com/tools/releases/platform-tools (or nixpkgs android-tools) Talk to the phone, reboot to download mode, patch headlessly
Stock firmware samfw.com — model SM-A055M, region GTO, build A055MUBU5CXH1 Source of the matching boot.img and vbmeta.img
Magisk github.com/topjohnwu/Magisk — Magisk-v30.7.apk Patch boot.img, grant root
Thor (Odin reimplementation) github.com/Samsung-Loki/Thor Flash on Linux where heimdall fails on modern Samsung
lz4 distro package / nixpkgs Decompress *.img.lz4 from the firmware tar

Things that did not work and why, so you don’t repeat them:

  • heimdall (brew/nixpkgs) detects the device but fails begin odin with Protocol initialisation failed! on this Samsung — its download protocol is too old. Thor handshakes fine.
  • samfirm.js / samloader CLIs hit 403 / Access Denied from Samsung’s FOTA server for this model+region, so the firmware was downloaded from samfw.com through a browser instead.
  • There is no init_boot partition in this firmware — the ramdisk is in boot.img (header v2). Patch boot.img, not init_boot.img.

Step 1 — allow the unlock

Section titled “Step 1 — allow the unlock”

On the phone: Settings → About phone → Software information → tap Build number 7× to unlock Developer options, then Settings → Developer options → OEM unlocking → on. If the toggle is greyed out, the phone has to be online for a while first (Samsung’s RMM/KG state); leave it on Wi-Fi with a SIM and try again later.

Step 2 — unlock the bootloader (wipes the phone)

Section titled “Step 2 — unlock the bootloader (wipes the phone)”

This factory-resets the device and trips Knox. On Samsung the unlock screen is not reachable with adb reboot download — that lands in plain Odin mode, which has no unlock prompt. Use the key combo:

  1. Power the phone off.
  2. Hold Volume Up + Volume Down together and plug in the USB cable; keep holding.
  3. On the blue warning screen, long-press Volume Up to reach the unlock screen, then Volume Up again to confirm. The phone wipes itself and reboots.

Step 3 — get boot.img and vbmeta.img from stock

Section titled “Step 3 — get boot.img and vbmeta.img from stock”

Download the exact firmware (SM-A055M / GTO / A055MUBU5CXH1) from samfw.com. It is one big *_fac.zip containing AP_*.tar.md5, BL, CP, CSC and HOME_CSC. You only need the AP. To avoid unpacking ~7 GB, stream just the two images out of it:

Step 4 — patch boot.img with Magisk (headless)

Section titled “Step 4 — patch boot.img with Magisk (headless)”

A racked phone has no screen to tap, so patch from the command line instead of the Magisk GUI. Unpack the APK’s native binaries (they ship as lib*.so) and its scripts, push them with boot.img to the phone, and run boot_patch.sh with the right flags — this is the trap that bootlooped the device the first time:

  • KEEPVERITY=true and KEEPFORCEENCRYPT=true — the Magisk app sets both for Samsung. With them false, boot_patch.sh strips fileencryption=…,keydirectory=/metadata/… from the fstab, /data won’t mount, and the phone reboots into the “data may be corrupt” recovery (rescue party) forever.
  • PATCHVBMETAFLAG=true — patches the vbmeta flags inside the boot image.

Failed to patch lines about the dtb during the run are normal — magiskboot patches verity in the dtb only where it finds the pattern. What matters is Repack to boot image: [new-boot.img] at the end.

Step 7 — flash with Thor

Section titled “Step 7 — flash with Thor”

heimdall cannot flash this phone; Thor (a .NET Odin reimplementation) can. Download the Linux build from its releases, make it executable, and run it. On NixOS a foreign ELF needs an FHS wrapper (steam-run); on an ordinary distro run it directly. Root is needed for raw USB, and the host’s cdc_acm module can grab the device in download mode — unload it if connect finds nothing:

Pick the device at connect, tick boot and vbmeta at flashTar, confirm. reboot normal boots straight into the system instead of shutting down. First boot with Magisk takes a minute or two; the “not running official software” warning on boot is expected now.

Step 8 — finish Magisk and grant root

Section titled “Step 8 — finish Magisk and grant root”

Install the Magisk app and open it; it asks to do additional setup and reboots once more. After that, root works, but the adb shell user is denied by default — grant it:

That su then works from the provider’s adb too, so the host — and Holtdroid’s agent — has root on the phone.

If it bootloops

Section titled “If it bootloops”

Flash the stock rollback tar from step 6 (stock boot.img + stock vbmeta.img) with Thor and reboot normal. The phone comes up unrooted, data wiped, bootloader still unlocked; re-enable USB debugging and start again from step 4 with the correct flags. A failed flash never bricks on its own: the device stays in download mode and can always be reflashed with full stock firmware.
