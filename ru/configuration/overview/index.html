Configuration files

How every Holtdroid service is configured, and the api's options.

Это содержимое пока не доступно на вашем языке.

Every service reads one YAML file passed with --config (the Helm chart renders them for you). Any key can be overridden by an environment variable: HOLTDROID_ + the key path in upper case with __ between levels. Matching is case-insensitive.

Logging is configured with flags or environment, not the file: --log-level / HOLTDROID_LOG_LEVEL (debug, info, warn, error) and --log-format / HOLTDROID_LOG_FORMAT (json, text).

Fields that hold credentials only accept secret references, never plain values — see Secrets.

Every service also reads two shared sections: telemetry (Prometheus metrics on a separate port, OpenTelemetry tracing) and, in the api and the ssh-gateway, audit (the audit log). Both are described in Monitoring and audit.

GPS map

Section titled “GPS map”

The GPS panel of a session shows a map: click it or drag the marker to fake the device’s position there, or click points for it to walk, run or drive through. The tiles come from OpenFreeMap, which needs no API key, through the api: the browser only talks to the portal, and the tile server sees the api’s address and User-Agent, never the user’s cookies.

Any server that keeps a MapLibre style, its TileJSON, tiles, sprites and glyphs under one base URL works, a self-hosted one included: the api rewrites map.url in JSON responses to its own proxy path. The api needs outbound HTTPS to it; nothing is stored, browsers cache the tiles.

GPS routes along roads come from a Valhalla server, through the api as well: by default the public FOSSGIS one, free and keyless under fair use. Walking and running use its pedestrian profile, driving auto; a route takes up to 18 clicked points.

A self-hosted Valhalla works the same; run your own if many people plan long routes, since the public server limits the rate and the distance.

IP geolocation

Section titled “IP geolocation”

The Routes and DNS tabs show the country and network of each server. The api looks them up in two MaxMind-format databases, which the image ships: this month’s DB-IP Lite country and ASN databases (CC BY 4.0), taken when the image was built.

Point them at other files to use newer databases or MaxMind’s GeoLite2 (GeoLite2-Country.mmdb, GeoLite2-ASN.mmdb), for example from a volume that geoipupdate refreshes; the api reads them at start. A file that isn’t there leaves its fields empty, which is what holtdroid dev gets unless you download them. Lookups stay inside the api; no address is sent anywhere.
